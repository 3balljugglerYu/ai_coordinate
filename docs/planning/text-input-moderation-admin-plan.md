# 文字入力の判定記録と「言葉の一覧」の管理画面 計画書

- 作成: 2026-10-11
- 状態: 計画のみ(未着手)
- 関連: 文字入力(docs/planning/name-input-slot-plan.md)、#718 / #719 / #720 / #721

## 1. 背景

文字入力の欄に入れた文字は、そのまま画像に描かれて、投稿で公開される。
そのため、生成の前(課金の前)に OpenAI Moderation API で文字を判定している(#718)。

本番で試した結果(2026-10-11)から、次の3段で止めている(#721)。

| 段 | 止め方 | 例 |
|---|---|---|
| ① API の判定 | `flagged` が立ったら止める | 死ね・殺す(暴力) |
| ② スコアの線 | 性的(sexual)のスコアが 0.33 以上なら止める | えっち・セックス・sexy・メスガキ・射精 |
| ③ 言葉の一覧 | 文字全体が一致したら止める | sex(0.243 でビキニと同じスコアのため、線では分けられない) |

①〜③の設定は、今はコードに直書きしている(`features/generation/lib/text-input-moderation.ts`)。
そのため、すり抜けた言葉を足したり、誤って止まった言葉を通したりするには、PR とデプロイが要る。

**ユーザーの方針(2026-10-11)**

- 一番よくないのは、問題ない言葉なのに止められ、それに使う人が気づくこと(例: 「ウルトラマンコスモス」が部分一致で止まる)。止めすぎない側に倒す。
- 運営が「何を入れて、何が通り、何が失敗したか」を管理画面で見られるようにする。
- 見た結果から、「sex」のように止める言葉を足したり、止まったけれど問題ない言葉を通したりできるようにする。

## 2. やること

1. **判定の記録**: 文字入力を使った生成ごとに、入れた文字・スコア・判定・画像の結果を残す。
   - 止まったものだけでなく、通ったものもすべて残す(ユーザー決定)。
2. **90日で自動削除**: 入れた文字には名前などの個人的な文字も含まれるため、90日たったら自動で消す(ユーザー決定)。
3. **管理画面**: 記録の一覧と、言葉の一覧(止める/通す)を見る・足す・消す画面。
4. **言葉の一覧をデータベースへ**: 運営が足した言葉が、デプロイなしですぐ判定に効くようにする。

## 3. データベース

### 3.1 `text_input_moderation_logs`(判定の記録)

| 列 | 型 | 内容 |
|---|---|---|
| id | uuid | |
| created_at | timestamptz | 判定した日時 |
| user_id | uuid | 生成した人(`auth.users`。退会時は NULL にする) |
| image_job_id | uuid NULL | 作られた生成(止めたときは NULL)。画像の結果はここから引く |
| source_post_id | uuid NULL | カタログから使った生成なら、その原作 |
| entries | jsonb | 判定した文字ごとの記録(下記) |
| decision | text | `passed` / `flagged_api` / `flagged_threshold` / `flagged_word` / `allowed_word` / `unavailable` |

`entries` の1件:

```json
{ "kind": "value", "text": "メスガキ", "flagged": false, "top": [["sexual", 0.377], ["sexual/minors", 0.196]] }
```

- `kind`: `value`(入れた文字)/ `label`(ラベル)/ `hint`(入力のヒント)
- `top`: スコアの高い種類を上から3つ(今のログと同じ形)

**画像の結果**は `image_job_id` から `image_jobs.status` / `error_message` を引いて出す。
「生成できた」「画像の AI に止められた(`safety_policy_blocked`)」「ほかの理由で失敗」に分ける。
記録の側には書き戻さない(二重に持たない)。

**権限(RLS)**: 一般の利用者は読めない・書けない。書くのはサーバー(service_role)だけ、読むのは管理画面(運営)だけ。

### 3.2 `text_input_word_rules`(言葉の一覧)

| 列 | 型 | 内容 |
|---|---|---|
| id | uuid | |
| word | text | 言葉(比べる形にそろえて保存する: NFKC・小文字・空白なし) |
| action | text | `block`(止める)/ `allow`(通す) |
| note | text NULL | なぜ足したか(例: 「スコアではビキニと分けられない」) |
| created_by | uuid | 足した運営 |
| created_at | timestamptz | |

- `word` は一意(同じ言葉を「止める」と「通す」の両方に入れられない)。
- どちらも**文字全体が一致したときだけ**効く(部分一致はしない。誤判定を出さないため)。
- 今コードに直書きしている「sex」は、このテーブルの最初の1行に移す。

### 3.3 90日での自動削除

pg_cron で毎日 `DELETE FROM text_input_moderation_logs WHERE created_at < now() - interval '90 days'` を実行する。
低トラフィック帯(JST 4:00 台)に入れる(既存の `20260611090000_schedule_db_log_tables_cleanup_cron.sql` と同じ書き方)。

## 4. 判定の流れ(変更後)

`app/api/generate-async/handler.ts` → `moderateTextInput`

1. 入れた文字・ラベル・入力のヒントを集める(今と同じ)。
2. **言葉の一覧**(DB。1分ほどキャッシュ)と照らす。
   - `allow` に一致した文字は、それ以降の判定をせずに通す。
   - `block` に一致したら、API に聞かずに止める(`flagged_word`)。
3. 残りを Moderation API に送り、`flagged` かスコアの線(性的 0.33)で判定する。
4. **記録を1行書く**(止めたときも通したときも)。
   - 記録の書き込みに失敗しても、生成は止めない(ログに警告だけ残す)。
5. 生成を作れたら、記録に `image_job_id` を入れる。

スコアの線(性的 0.33)は、今回はコードのまま残す。
線を変えたくなったら、記録のスコアを見てから相談する(管理画面で変えられるようにするのは、必要になってから)。

## 5. 管理画面

管理画面のメニューに「文字入力の判定」を足す(`app/(app)/admin/admin-nav-items.ts`)。

### 5.1 記録の一覧

| 日時 | ユーザー | 入れた文字(種類) | スコア | 判定 | 画像の結果 | 操作 |
|---|---|---|---|---|---|---|
| 10/11 18:14 | 〇〇さん | メスガキ(入れた文字) | 性的 0.377 | 線で止めた | — | 問題なしにする |
| 10/11 18:13 | 〇〇さん | sex(入れた文字) | 性的 0.243 | 通過 | 生成できた | 止める言葉にする |

- 絞り込み: 「止まったもの」「通ったもの」「画像の AI に止められたもの」
- 新しい順。1ページ 50件。
- **「止める言葉にする」/「問題なしにする」**ボタンで、その文字を言葉の一覧に足す(メモも書ける)。
- 運営アカウント(内部アカウント)の試しも記録に出る。見分けられるよう、名前の横に「運営」と出す。

### 5.2 言葉の一覧

- 「止める言葉」「通す言葉」を、足した日・メモと一緒に一覧で出す。
- 手で足す・消すこともできる。
- 足したり消したりしたら、監査ログ(`audit-log`)に残す。

## 6. プライバシーポリシー

今のプライバシーポリシー(`app/(marketing)/privacy/page.tsx`)の確認結果:

- 取得する情報に「入力プロンプト、…等の生成パラメータ」がある。文字入力の文字もこれに含まれる。
- 利用目的に「安全性向上、不正利用検知、モデレーション、…の範囲で、ユーザーコンテンツを内部的に解析・保管することがあります」がある。
- 外部サービスとして「画像生成 API 提供元(OpenAI、Google 等)」がある。

→ **今の記載で、記録の保存と OpenAI での判定はカバーできている**と考えている。新しく同意を取り直す必要はない見込み。

ただ、分かりやすさのため、次の追記を実装と同じタイミングで入れることを提案する(ユーザーの確認後)。

- 取得する情報: 「生成時に入力した文字(文字入力の欄に入力した文字を含む)」
- 保存期間: 「不適切な文字の判定記録は、90日を経過したものから自動で削除します」

⚠️ 法律の専門家の確認は受けていない。気になる点があれば、公開前に専門家に確認する。

- Edge Function(image-gen-worker)の変更は無い見込み(判定は Next.js の受付で行うため)。

## 8. 決まっていること・決まっていないこと

**決まっていること(2026-10-11 ユーザー決定)**

- 記録は止まったもの・通ったもの、すべて残す
- 90日たったら自動で消す
- 性的のスコアの線は 0.33。「sex」は文字全体の一致で止める
- 部分一致では止めない(止めすぎない)

**実装の前に確かめること**

- プライバシーポリシーの追記の文言
- 管理画面で、ユーザー名をどこまで出すか(ニックネームだけ、など)
