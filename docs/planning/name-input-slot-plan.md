## 1. 背景と目的

- 「うちの子の名前を画像に入れたい」という要望がある（神コレクション、名前入りのカード・診断イラストなど）。
- 今のプロンプトは「名前の入力がある場合は…、未入力の場合は…」と、**入力があるかどうかの判断を画像の AI に任せている**。画像の AI はこの判断を間違えることがある（名前を勝手に作る、空欄なのに名前欄を描く など）。
- 神コレクションは、名前を本文の決まった位置に入れず、末尾に付け足す方式で無理に扱っている（`shared/generation/style-prompts.ts:71-86` の `appendUserPromptSection`）。

**目的**：プロンプトに名前の目印を書いておくと、**生成する人が名前を入れられ、サーバーが「名前あり／なし」を決めてから AI に送る**。ガチャプロンプトで作ったもの一式を、名前の欄の版としてそろえる。

## 2.1 改訂：名前に限らず「文字入力」として出す（2026-10-07 ユーザー決定）

実機で試した結果、8文字以内なら名前以外（好きな言葉・四字熟語など）も入れられることが分かった。名前専用ではなく、**好きな文字を入れてもらえる機能**として出す。

| 項目 | 改訂後 |
|---|---|
| スイッチの文言 | 「**文字入力を受け付ける**」（箱の名前は「**プロンプトオプション**」。#706） |
| 見出し・入力例 | **作る人が決められる（全員）**。画面では「**ラベル**」（説明：ユーザーに、何を入力する欄なのかを示す名前です。）と「**入力のヒント**」（説明：ユーザーに、うすい灰色で表示される入力例です。空欄のときだけ表示され、入力すると消えます。） |
| 任意/必須 | **いつも任意**。必須にできるのはサブスクの構想（#708 で画面から外した。手書きの `{{INPUT*:…}}` は今も必須として通る） |
| 長さ | **8文字のまま**。長くできるのはサブスクの構想 |
| AI への固定文 | 名前専用の文から、**作る人の見出しを入れた汎用の文**へ（下）。どこにどう描くかは本文が書く |
| 投稿の札 | 「**文字入力✔︎**」（「名前入り」から変更） |
| 本文から作る道具 | 名前だけでなく、使う人に入れてもらう文字の行を見つける（「本文から文字入力の欄を作る」） |
| 紹介ページ | 「好きな文字を入れられる」機能として作る |

固定文（`shared/generation/name-input.ts`）：

```
【好きな言葉】「一期一会」
この文字を正式なものとして固定し、変更・省略・言い換え・翻訳・英字化はしないでください。
画像内に最低1回、「一期一会」をそのまま表示してください。
```

空欄のとき：

```
【好きな言葉】未入力
「好きな言葉」にあたる文字は作らず、画像にも表示しないでください。
```

コードの名前（`nameInput`・`NamePromptField` など）とフラグ `NEXT_PUBLIC_NAME_INPUT_ENABLED` は、名前専用だった頃のまま残す（付け替えは手間に見合わない）。

## 3. 仕組み

### 3.1 目印の書き方

```
{{INPUT:キャラクターの名前}}        ← 任意（空欄OK）
{{INPUT*:キャラクターの名前}}       ← 必須
```

- コロンの後ろが、**使う人に見える入力欄の見出し**。作る人がスイッチの設定（見出し・任意/必須）を変えると、本文の目印もそれに合わせて書き換わる。
- 1つのプロンプトに名前の欄は**1つまで**（一般の利用者）。運営は制限しない（ガチャと同じ `gachaLimitsFor` の考え方）。

### 3.2 送る直前の置き換え（サーバー）

目印は、画像の AI に送る直前に、Worker が固定の文に置き換える（`expandGachaPrompt` と同じ場所。`supabase/functions/image-gen-worker/index.ts:2214` 付近）。

| 入力 | 置き換える文（日本語の固定文） |
|---|---|
| 名前あり（例「ぺるこ」） | 【名前】「ぺるこ」<br>この名前を正式名として固定し、変更・省略・言い換え・英字化はしないでください。<br>画像内に最低1回、「ぺるこ」をそのまま表示してください。 |
| 空欄 | 【名前】未入力<br>名前は付けず、名前欄やキャラクター名の表示はしないでください。 |

- 本文に残っている「名前が入力されている場合のみ…」のような文も、**答えが分かった状態**で AI が読むので迷わない。
- 置き換えの順番は**ガチャの後**。選ばれなかったガチャの中身に目印があっても、一緒に消える。

### 3.3 名前の扱い（安全）

- 8文字まで。**`{{` `}}`・改行・制御文字・ゼロ幅文字は受け付けない**（目印やガチャの囲みを作られないように）。前後の空白は落とす。
- 確かめるのは画面・サーバーの受付（`features/generation/lib/schema.ts`）・**Worker の3か所**。
  - Worker でも確かめるのは、`image_jobs` の行を作成後に本人が書き換えられるため（memory: image_jobs 行が書換可能）。
- 名前は**かぎかっこの中の「描く文字」としてだけ**使う（固定文の中に入れる）。

### 3.4 名前をどこに持つか

- 受付 → Worker：`image_jobs.generation_metadata.nameInput`（本人の行。本人以外は読めない）。
- **成功時に投稿側（`generated_images.generation_metadata`）へ写すときは、名前を消して `nameInputUsed: true` だけを残す**（`shared/generation/job-metadata.ts` の `mergeSuccessGenerationMetadata`）。
  - `generated_images.generation_metadata` は公開の投稿で読めるため（ホームのフィードなど）。
  - 失敗時の経路（`index.ts:3524`）でも同じく消す。
- 作る人の保存されるプロンプトには**目印のまま**残る（今のガチャと同じ。`generated_image_prompt_secrets` へ写るのは DB の author_input で、名前は入らない）。

### 3.5 使う人の画面に見出しを出す（本文は送らない）

- カタログから使う人には、**見出しと任意/必須だけ**を返す API を新しく作る：`GET /api/posts/[id]/prompt-slots`
  - 認可は今の `prompt-text`（`app/api/posts/[id]/prompt-text/route.ts`）と同じ `validate_derived_prompt_source`。
  - 本文から目印を読み取り、`{ nameInput: { label, required } | null }` だけを返す。**非公開のプロンプトでも、本文は返さない**。
- 生成シート（`PromptLockedGenerationSheet.tsx:178-186`）で、画像の下に名前の欄を出す。

## 4. EARS（要件）

| ID | 要件 |
|---|---|
| REQ-001 | 作る人が「名前を入れられるようにする」をオンにすると、見出し・入力例・任意/必須の設定が開き、本文に目印が入る |
| REQ-002 | 作る人の生成でも、試しの名前を入れられる（作る人も使う人の一人） |
| REQ-003 | カタログから使う人の生成シートに、画像の下に名前の欄を出す。見出しは作る人が決めたもの |
| REQ-004 | 名前は8文字まで。`{{` `}}`・改行・制御文字・ゼロ幅文字は、画面・受付・Worker で受け付けない |
| REQ-005 | 必須のときに空欄なら生成できない。任意のときは空欄で生成でき、「名前なし」の固定文に置き換わる |
| REQ-006 | 一般の利用者は、1つのプロンプトに名前の欄は1つまで（受付でも止める）。運営は制限しない |

| REQ-009 | 「本文から名前の欄を作る」：AI が名前に関する行（【名前】・名前の条件の※など）を見つけ、目印1つにまとめる案を出す。採用したときだけ書き換え、作れたときだけ5ペルコインを使う |
| REQ-010 | 紹介ページ `/guide/name`（仮）を新しく作り、スイッチの右に「使い方はこちら」を付ける |
| REQ-011 | 神コレクションの12件を、目印を使う方式に作り直して入れ替える。入れ替えの前後で同じキャラクター・名前で生成して見比べる |
| REQ-012 | 文字はすべて15言語に対応する |

## 5. ADR（設計判断）

- **ADR-1：名前は Worker が固定文に置き換える**（ガチャと同じ場所）。AI に「入力があれば…」の判断をさせない。
- **ADR-2：名前は `image_jobs.generation_metadata` で運び、投稿側には残さない**。プロンプトを伏せるテーブル（`generation_prompt_snapshots`）に列を足す案もあるが、CHECK 制約と RPC の作り直しが要り、名前は秘密というより「公開の投稿に載せない」ものなので、こちらにする。
- **ADR-3：使う人には見出しだけを返す API を新しく作る**。投稿の一覧のデータに見出しを足す案は、キャッシュ（`prompt-action-cache.ts` の `"use cache"`）で古い値が残るおそれがあるため取らない。
- **ADR-4：「プロンプトの仕掛け」の箱にまとめる**。ガチャのチェックもスイッチに作り替える。のちに選択の枠などが増えても、同じ箱に1行足すだけで済む。
- **ADR-5：神コレは、今の付け足し方式を消さずに残し、作り直したプリセットだけ新しい方式にする**（#675 の ADR-005 と同じ）。One-Tap Style の生成（`app/(app)/style/generate-async/handler.ts`）でも、プリセットの本文に目印があれば同じ置き換えを使う。今の入力欄の設定（`preset_categories` の `show_user_prompt_input`・見出し・最大10文字）は、8文字に合わせる。

## 7. テストの観点

- 名前の検査：8文字ちょうど／9文字、`{{`・改行・ゼロ幅文字、前後の空白
- 置き換え：名前あり／空欄／必須で空欄（受付で止まる）、ガチャと一緒に使ったとき（順番）
- 受付と Worker の両方で同じ検査が効く（Worker は行の書き換えに備える）
- 投稿側の記録に名前が残らない（成功・失敗の両方）
- 見出しの API：非公開のプロンプトでも本文を返さない、使えない人には返さない
- 札：ガチャと名前入りが両方あるとき横に並ぶ／どちらか一方
- 15言語の文言のそろい

## 8. やらないこと（この計画では）

- 名前以外の入力の枠（自由な文の入力・選択の枠）。#675 の Phase 3 以降で扱う
- 名前の欄を2つ以上にする（課金で広げる余地として残す）
