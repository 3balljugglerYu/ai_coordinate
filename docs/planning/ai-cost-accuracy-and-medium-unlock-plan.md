# AI原価の実測是正と、無課金ユーザーへの Medium 開放

作成日: 2026-08-14
関連: `features/admin-dashboard/lib/ai-cost-rates.ts` / `features/generation/lib/model-config.ts`

## 背景

「無課金ユーザーにもレンダリング品質 Medium を開放したい」という検討から始まった。
理由は2つ。ペルコインを消費してもらうことと、より良い画像を作ってもらうこと。

判断のために原価を確認したところ、**推定原価そのものが実額と大きくずれていた**ことが分かった。
先に原価を正しくしないと、開放後に増えた実額の原因を取り違える。そのため2つを1つの PR で扱う。

## 分かったこと

### 1. 単価表は「出力ぶん」しか数えていなかった

1生成の原価は3つの合計でできている。

```
出力画像トークン ＋ 入力画像トークン ＋ 入力テキストトークン
```

`ai-cost-rates.ts` は OpenAI が公表している「1024x1024 の1枚あたり価格」を転記していたが、
これは**出力ぶんだけ**の価格である。OpenAI のドキュメントにも、入力トークンは別途
考慮が必要であること、gpt-image-2 は入力画像を常に高精細で処理することが明記されている。

Persta は `images/edits` に**必ず入力画像を送る**うえ、One-Tap Style は数千文字の
プロンプトを送る。この2つがまるごと計上漏れしていた。

### 2. 実測結果（2026-08-14）

本番と同じ正規化をかけた入力画像（1592x2048）1枚と、アプリが実際に指定する出力サイズ
（1104x1424）で `images/edits` を叩き、レスポンスの `usage` を読んだ。

| | 入力画像 | 出力画像 | 実原価 | 単価表 | 乖離 |
|---|---:|---:|---:|---:|---:|
| low | 1,496 tok | 172 tok | ¥2.67 | ¥0.93 | 2.88倍 |
| medium | 1,496 tok | 1,587 tok | ¥9.25 | ¥8.22 | 1.13倍 |
| high | 1,496 tok | 6,345 tok | ¥31.38 | ¥32.71 | 0.96倍 |

**入力画像トークンは 1,496 で完全に一定**だった。品質を変えても、出力サイズを
1024x1024 から 1104x1424（ピクセル1.5倍）に変えても 1トークンも動かない。

つまり**出力サイズは原価にほとんど影響しない**。当初「1k tier は実際には
1024x1024 ではなく約1.5倍のピクセルで出力しているから原価も1.5倍のはず」と
見立てたが、これは誤りだった（実測 0.96倍）。

### 3. 本番プロンプトを含めた実測

One-Tap Style の `provider_prompt` は中央値 4,282文字・p90 18,360文字・最長 25,406文字。
実物を使って測り直した。

| 条件 | text tok | 実原価 | 原価/pc |
|---|---:|---:|---:|
| One-Tap Low（中央値） | 988 | ¥3.42 | ¥0.342 |
| One-Tap Low（p90） | 3,505 | ¥5.37 | ¥0.537 |
| One-Tap Low（最長） | 4,770 | ¥6.35 | ¥0.635 |
| Medium（中央値） | 988 | ¥10.00 | ¥0.500 |
| High（中央値） | 988 | ¥32.12 | ¥0.642 |

テキストトークンは品質に依存しない（p50 で low/medium/high とも 988 で一致）ため、
未測定のセルは加算で求まる。計算モデルは実測5点を ¥0.005 以内で再現する。

| プロンプト | Low (10pc) | Medium (20pc) | High (50pc) |
|---|---|---|---|
| 中央値 4,282字 | ¥3.42（¥0.342） | ¥10.00（¥0.500） | ¥32.12（¥0.642） |
| p90 18,360字 | ¥5.37（¥0.537） | ¥11.95（¥0.598） | ¥34.08（¥0.682） |
| 最長 25,406字 | ¥6.35（¥0.635） | ¥12.93（¥0.647） | ¥35.06（¥0.701） |

**プロンプトを伸ばすと、品質によらず一律 ¥2.93 増える**（中央値→最長）。
Low ではそれが原価の +86%、High では +9% にあたる。
Low の原価はほぼ全部が入力ぶんで、出力画像は ¥0.80 しかかかっていない。

### 4. 未登録モデルが原価ゼロで消えていた

`MODEL_COST_RATES` に登録されていたのは `-1k` の3つと Gemini 3種だけだった。
未登録のモデルは `getModelRate()` が null を返し、`buildAiCostEstimate` が
**金額に加算せず件数だけ数える**ため、原価が丸ごと 0 円として消える。

漏れていたもの: `gpt-image-2-*-2k` / `*-4k` の6種、legacy alias `gpt-image-2-low`（350件）、
`gemini-2.5-flash-image`（401件）、`gemini-3.1-flash-image-preview-512`（365件）、
`gemini-3-pro-image-2k`（8件）、`gemini-3-pro-image-4k`（17件）。

## ADR

### ADR-005: 原価を「出力＋入力画像＋テキスト」の合計で数える

- **Context**: 出力ぶんだけを数えていたため、主力の One-Tap Style Low で実額の
  1/4〜1/7 しか表示できていなかった。
- **Decision**: `AiModelRate` を `outputUsd` / `inputImageUsd` に分解し、
  テキストぶんは `generation_type` ごとの推定トークン数で加算する。
  gpt-image-2 の値は実測値を使う。
- **Reason**: 入力ぶんは Low で原価の7割を占める。無視できる誤差ではない。
  実測すれば固定費として正確に置ける。
- **Consequence**: 単価表がモデルごとの1個の数字ではなくなり、構造が複雑になる。
  代わりに「なぜその金額なのか」が読めるようになり、再測定もしやすい。
  過去期間の表示金額は増える（下がることはない）。

### ADR-006: 2k / 4k は実測せず外挿する

- **Context**: 2k/4k の実測には API 実費 約$1.9 がかかる。
- **Decision**: 1k の実測値を tier のピクセル上限比で外挿し、`basis: "derived"` を付ける。
- **Reason**: 直近30日の利用が4件（全体の0.3%）。原価ゼロで消えているよりは
  外挿値のほうが正確で、実費に見合わない。
- **Consequence**: 2k/4k の金額は不正確。しかも 1k の実測で「出力サイズを1.5倍に
  しても出力トークンは増えなかった」ことから、**ピクセル比例の仮定は過大側に
  振れている可能性が高い**。精度が要るようになったら実測して置き換える。

### ADR-007: Medium は無課金にも開放し、High は有料のまま残す

- **Context**: 無課金ユーザーの品質選択を広げたい。ただし原価と有料プランへの影響が懸念。
- **Decision**: `FREE_PLAN_ALLOWED_MODELS` に `gpt-image-2-medium-1k` を追加する。
  High と 2k/4k はロック維持。ゲスト（未ログイン）は Low のみのまま。
- **Reason**: 1ペルコインあたりの原価で見ると Medium（¥0.500〜0.647）は
  Low（¥0.342〜0.635）とほぼ同じ帯に収まる。長いプリセットでは
  **One-Tap Low のほうが Medium より割高になる逆転すら起きる**。
  無課金ユーザーはその最も割の悪い選択肢を今すでに制限なく使えているので、
  Medium を足しても原価の上限は実質的に動かない。
  High は ¥0.642〜0.701 と一段高いので線を引く根拠がある。
  有料プランの価値の本体は月次ペルコイン付与・同時生成枚数・ストック数・
  ボーナス倍率であって、品質ロックではない。
- **Consequence**: 無料ペルコインの消費が速くなり、無料枠ぶんの実費は増える
  （デイリー投稿ボーナス20pcを使い切る想定で ¥6.84〜10.74/日 → ¥10.00/日）。
  ゲストには開けていないので、**ログインの動機としては残る**。

## 再測定の手順

単価改定やモデル追加のときは、`.local/` に置いた測定スクリプトを使う
（`.gitignore` 済み・リポジトリには含めない）。

1. 本番と同じ正規化（長辺2048 / JPEG80）をかけた入力画像を用意する
2. `images/edits` に `model=gpt-image-2` / `size` / `quality` を指定して叩く
3. レスポンスの `usage.input_tokens_details.image_tokens` / `.text_tokens` /
   `usage.output_tokens` を読む
4. `text×$5 + image_in×$8 + output×$30`（per 1M）で USD を出す

**APIキーはスクリプトに直接読ませ、標準出力には出さないこと。**
プロンプト本文も出力しない（PROMPT-SECRECY）。
