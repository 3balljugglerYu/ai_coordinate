# 完走投稿を通常の投稿詳細で開く（いいね・コメント対応） 実装計画書

作成日: 2026-08-09
ステータス: 承認済み・実装完了

## ゴール

完走フィード投稿（book/mount）をタップしたとき、没入シェアページ（`/m/{id}[/book]`）へ直行する現仕様をやめ、**他の投稿と同じ「投稿詳細画面」**を開く。詳細画面でいいね・コメントができ、没入ビューへは詳細内の汎用 CTA ボタンから遷移する。

## 決定事項（ユーザー確定 2026-08-09）

| 項目 | 決定 |
|---|---|
| タップ先 | フィード等 → **通常の投稿詳細**（`/posts/{id}`）。没入ビューは詳細内 CTA から1タップ |
| CTA ラベル（汎用・15言語） | book 型 → **「📖 めくって見る」**／mount 型 → **「✨ カードを見る」**（「台紙」という語は使わない） |
| X シェア URL・OGP | 変更なし（`/m/{id}[/book]` のまま。外部流入は従来どおり没入ビュー着地） |
| 投稿フロー | 変更なし（完走画面の「ホームに投稿する」・オプトイン・完走ごとに最大1行） |

## コードベース調査結果（2026-08-09 検証済み）

| 対象 | 場所 | 現状と含意 |
|---|---|---|
| 完走投稿のデータ | `generated_images` 行（`completion_id` + `completion_view_mode`、RPC `create_collection_completion_post`） | 通常投稿と同じテーブル → **いいね・コメント基盤は既存**。カード上のいいねは現在も動作 |
| タップ先の決定 | `getPostCardHref(post, locale)`（PostCard から使用） | 完走分岐を1箇所で解消できる。他の呼び出し元(検索・プロフィール等)も実装時に洗い出して同時に直る |
| 詳細ページの強制転送 | `app/posts/[id]/page.tsx` の `completionRedirect`（`is_posted=true` のとき `/m/…` へ redirect） | **コメント通知のディープリンクも没入ページへ飛ばされていた**。撤去対象。取消済み投稿の通常詳細フォールバック(MUST-ADDRESS-007)は維持 |
| 詳細ページのメタデータ | 同ページ冒頭で完走投稿は canonical/OG url を `/m/…` に向けている | 通常投稿と同じ `/posts/{id}` 正規化へ変更 |
| カードのコメント数 | `PostCard.tsx` `!post.completion_id` で**意図的に非表示**（旧タップ先にコメントUIが無いため: MUST-ADDRESS-011） | 根本原因が解消されるため表示に戻す。prefetch も有効化 |
| マイページ生成一覧 | `completion_id IS NULL` で除外 | 現状維持（ツール生成一覧の意味論。変更しない） |
| 詳細画面の生成系UI | プロンプト欄・One-Tap カード・Before 画像等 | 完走投稿は `style_template_id`/プロンプト/`pre_generation_*` が NULL のため大半は自然に非表示になる見込み。実装時に実データで確認し、必要なら `completion_id` で明示抑制 |

## ユーザーストーリー（合意済み）

- 閲覧者: フィードでタップ → 投稿詳細（いいね・コメント可）→ CTA「📖 めくって見る／✨ カードを見る」→ 没入ビュー
- 投稿者: 投稿フローは不変。コメント通知から**コメントが見える詳細**に着地できるようになる
- X 流入者: シェア URL は従来どおり没入ビュー（変更なし）

## EARS（主要要件）

- When ユーザーがフィード・検索・プロフィール等で完走投稿をタップする, the system shall 通常の投稿詳細（`/posts/{id}`）を開く
- When 投稿詳細が完走投稿を表示する, the system shall コンプリートバッジと、`completion_view_mode` に応じた汎用 CTA（book=めくって見る／mount=カードを見る）を表示する
- When CTA をタップする, the system shall `/m/{completion_id}`（book は `/book`）へ遷移する
- While 完走投稿の詳細を表示中, the system shall 通常投稿と同じ いいね・コメント・通報等の操作を提供する
- Where 投稿が取消済み（`is_posted=false`）, the system shall 従来どおりのフォールバック挙動を維持する
- 不変条件: シェア URL・OGP・X 応募動線・投稿作成フローに変更を加えない
