# Vercel の関数リージョンを syd1 に固定している理由

`vercel.json` の `regions: ["syd1"]` は**意図的な設定**で、消すと画面全体が目に見えて遅くなる。
JSON にはコメントを書けないため、理由をここに残す。

## 何が起きていたか（2026-08-22 調査）

投稿詳細を開くと本文が出るまで **3.7秒** かかっていた（本番・実測）。

| | |
|---|---|
| スケルトン表示 | 0.36秒 |
| **本文が出る** | **3.70秒** |

グリッド表示（`<Link prefetch>` あり）でも 3.88秒で、**prefetch の有無は原因ではなかった**。

サーバー応答を分解すると、TTFB は 0.13秒（静的シェルは Vercel キャッシュ HIT）で速く、
残り約3秒はすべて動的部分のレンダリングだった。

## 原因：計算とデータが地球の反対側にあった

DB へ単純なクエリを1本投げて測った。

```
GET /rest/v1/profiles?select=user_id&limit=1
  実測                              220〜270ms
  x-envoy-upstream-service-time         1ms   ← DB の実処理
```

**DB の処理は 1ミリ秒で、残り 220ms はすべてネットワーク。** 配置はこうなっていた。

| | 場所 | 確認方法 |
|---|---|---|
| ユーザー | 日本 | |
| Vercel エッジ | hnd1（東京） | `x-vercel-id: hnd1::iad1::...` の1つ目 |
| **Vercel の関数実行** | **iad1（米・バージニア）** | 同・2つ目。`regions` 未指定時の Vercel 既定値 |
| **Supabase の DB** | **Oceania（シドニー）** | `supabase projects list` |

投稿詳細は 8〜12 回クエリを投げるので、**220ms × 10 ≒ 2.2秒**。観測した3秒と整合する。

## なぜ「DB の隣」に置くのが正解か

往復回数が支配的だから。ユーザーと関数の距離は**1往復ぶんしか効かない**が、
関数と DB の距離は**クエリの数だけ効く**。

- 変更前: 日本 → 東京エッジ → バージニア関数 →（シドニー DB を10往復）
- 変更後: 日本 → 東京エッジ → シドニー関数 →（同居 DB を10往復・各数ms）

しかも **東京→シドニー（約110ms）は東京→バージニア（約160ms）より近い**ので、
ユーザーから見た1往復ぶんも悪化しない。

## トレードオフ（許容できると判断した根拠）

Vercel の関数から同期的に叩く外部サービスは、シドニーからだと US まで遠くなる。

| 呼び出し元 | 影響 |
|---|---|
| **画像生成の本流** | **影響なし。** Supabase Edge Function `image-gen-worker` で動いており Vercel を経由しない |
| ゲスト生成・プリセットのプレビュー生成 | OpenAI / Gemini への往復が +100〜150ms 程度。ただし生成自体が20〜60秒かかるので比率として無視できる |
| Stripe（チェックアウト・ポータル・Webhook） | 1回きりの呼び出しで +100〜150ms。体感に出ない |
| Resend（問い合わせメール） | 同上 |

## 将来この設定を変えるとき

**Supabase のリージョンを東京へ移したときだけ**、`hnd1` へ変えること。
DB がシドニーのまま関数だけ東京へ戻すと、調査前の状態（1クエリ 220ms）に逆戻りする。

DB を東京へ移せば「ユーザー・関数・DB がすべて東京」で理想形になるが、
Supabase はプロジェクトのリージョン変更を後から行えないため、
新規プロジェクトを作ってデータ移行する必要がある（本設定はその移行を待たずに効く）。

## 残っている改善余地（本設定とは別）

1. **`getPost` が1リクエストで2回実行される。** `generateMetadata` は通常クライアント、
   `CachedPostDetail` は admin クライアントで呼ぶため引数が異なり、`React.cache` の
   重複排除が効いていない。1回あたり2往復なので4往復が2往復になる
2. **`generateMetadata` の `getImageDimensions` が画像を64KB取得している。**
   OGP の width/height 用だが、`generated_images.width/height` が 1358件中1326件（98%）で
   埋まっているので、DB の値を使えば1往復まるごと消える
3. フィードカードがカード地の `router.push` で遷移しており prefetch が効いていない
   （`PostCard` は `<Link prefetch>`）
